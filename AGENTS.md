# once-campfire-fsharp-thedotnetway

**This repository is theDotNetWay**, the third Campfire in F# (branch `dotnetway`), forked from the published F# port
(`ckluis/once-campfire-fSharp` at `a78972f`). It is the most .NET way possible: framework-first (ASP.NET Core, EF Core, Falco
and Falco.Markup, mainstream NuGet packages), the least and most familiar code, the UI pixel-identical to Rails, and several
times Rails' speed. Read `plans/dotnetway.md` first.

- **`plans/dotnetway.md` and the D1-D9 decisions** (`/Users/clank/Desktop/projects/campfire-fsharp-thedotnetway-plan.md`)
  **win wherever they conflict with the port's rules below.** In particular:
  - "Match Rust's implementation" no longer applies: `rust/` and `reference/` say *what* Rails does; *how* is the framework's.
    Don't port a Rust module when a framework feature or a mainstream package does the job; hand-written code only where
    parity demands it.
  - "Use the framework" does apply: controllers take `HttpContext` (not `Ctx`), views are Falco.Markup (not the UTF-8 writer),
    data goes through EF Core (not hand-written SQL), Cable runs on ASP.NET Core's WebSocket middleware.
  - The port's performance rules (pooled UTF-8 rendering, no markup library, prepared statements, Rust's caches) are withdrawn;
    the speed bar is the plan's floor of 5x Rails per workload, measured with `bench/quick`.
  - Differences from the port and from Rails follow the plan's known-differences policy (section 4), not "match byte for byte".
- **The image is `campfire-dotnetway:app`** (renamed in Phase 0: `parity/bin/candidate`, `Dockerfile`, `bench/run`/`bench/quick`). The port's
  `campfire-fsharp:app` stays usable as the comparison app (`PARITY_CANDIDATE_APP=fsharp`, `bench/run --apps ...,fsharp,dotnetway`); wherever the
  port guide below says `campfire-fsharp:app`, read `campfire-dotnetway:app`, and `bench/quick` measures `dotnetway` by default.
- `bin/kloc` counts the code by upstream's rules, per project.

What follows is the port's guide, still accurate for the code as it is until each layer is replaced.

Campfire in F#. It is a port that has to be indistinguishable in use from the Rails app in
`reference/` (basecamp/once-campfire, pinned at `90b3300`) and from the Rust port in `rust/`
(basecamp/once-campfire-rust, pinned at `ccece30`). It must also be faster than the Rust port on
every benchmarked workload.

## Sources of truth, in order

1. **`rust/` is what we translate from.** It already reproduces Rails exactly, and its tests and
   golden vectors prove it. Port a Rust module to F# with the same responsibilities and function
   boundaries, and port its tests with it. Rust's "Known differences" (`rust/README.md`) are ours
   too: same cookies, same CSRF policy, same job model, same limits.
2. **`reference/` is the oracle** for anything Rust doesn't settle or that looks wrong. When in
   doubt about behavior, read the Ruby. When it depends on Rails or gem internals, read the gem
   source in the reference image (`docker run --rm campfire-reference bundle show <gem>`).
3. **Bugs are the one exception.** We may fix a bug instead of copying it. Every deliberate
   divergence goes under "Known differences" in `README.md`, citing the reference file, and gets a
   test plus any parity mask it needs.

Stay compatible with existing installs: the SQLite schema, the storage layout
(`/rails/storage/{db,files,backups}`) and signed or encrypted cookies, so nobody is signed out by
an upgrade and rolling back to Rails works on data we wrote.

Don't edit `reference/`, `rust/` or `vectors/`. Vectors are generated by the reference app (see
`vectors/README.md`).

## F# conventions

- Modules and functions first. Use records and unions for data, and classes only where .NET
  interop needs them (ASP.NET Core hosting, `IDisposable` resources).
- `Result` for expected failures a caller handles (bad signature, record not found, invalid
  params); exceptions for bugs and broken invariants.
- `task { }` for async. No `Async` on hot paths, and no `.Result` or `.Wait()`.
- Match the shape of the Rust code you're porting: if it is one function there, it is one function
  here, with the same name in F# casing. Cite the Rust file at the top of each module
  (`// Port of rust/crates/db/src/messages.rs`). Cite the reference file when matching Rails
  directly, and say why when diverging.
- Comments only where behavior is non-obvious. Write code that reads like the code around it.
- Shared package versions live in `Directory.Packages.props`. Ask before adding a package Rust has
  no equivalent of.

## Performance rules (the hot paths are the five benchmarked workloads plus Cable fan-out)

- Render templates straight into pooled UTF-8 buffers (`IBufferWriter<byte>` / `ArrayPool`), never
  through intermediate strings, a DOM or a markup library.
- No reflection-based serialization on request paths; use `Utf8JsonWriter` or source-generated
  `System.Text.Json`.
- **Hybrid reads: the per-request READ paths are Dapper** (`src/Campfire.Db/Ef/FastReads.fs`, the only file that calls Dapper; `bin/verify`
  greps for it). That covers the session, user, account, room (by id, original, through the membership join), membership, message
  (by id, last page, page before), the account logo blob, the sidebar's four reads, the recent searches and the reachable-messages
  search. A new hot read goes there too: explicit column list (a column left out of a SELECT silently defaults), parameters only,
  string-backed enums through a private row record, an equivalence test against EF in `FastReadsTests.fs`. EF Core keeps every write,
  every cold query, the model, the schema and the interceptors. Reads open the context's own connection through EF and pass
  `CurrentTransaction` inside writes. Cold or rare reads stay EF.
- Queries are EF LINQ with `EF.Parameter` around every captured value (plans/design-data-ef.md, the LINQ-first revision);
  `FromSql`/`ExecuteSql` only where LINQ can't say it or a workload fell under the floor, each recorded in the Phase log. Nothing
  compiles in steady state (hot-path test H1 counts compilations). Reads run on pooled contexts; every write goes through
  `Writes.run`, one at a time behind the `WriteGate`.
- Anything Rust caches (page parts, ETags, gzip output, avatar paths), we cache the same way.
- Performance changes come with before-and-after numbers from `bench/`, recorded under
  `bench/results/`.

## Working rules

  then every test. Say exactly what ran and what didn't.
- Golden-vector tests read `vectors/*.json` through `tests/Shared/Repo.fs` (`Repo.vector "name"`).
- `bin/db-differential` compares `Campfire.Db` with the reference app: the fixtures and a long scenario
  loaded through Active Record against what the F# models write, the schemas, and the reference booting on
  a database F# wrote. It needs the reference image and colima; run it after changing a model or the schema.
- **Integrations (Phase 8; `plans/design-jobs.md` is the design).** Outbound HTTP is the three named clients of `Integrations/Clients.fs` ("opengraph", "webhook", "push"), each with its own policy and the guard at connect (`Guard.fs`); `Net.fs` holds only `IResolver` and `IDialer` (tests replace both through DI; `IntegrationsSupport` has the fakes and `FakeServer`, a raw-socket route table). The Net::HTTP replica, the Ruby URI parser and the hand-written push encryption are gone, so do not look for them. Its tests: `ClientsTests` (guard, limits, `readLimited`), `OpengraphTests` (the 90 recorded cases plus the class B probes), `WebhookTests` (19 recorded cases), `WebPushTests` (WP1 decrypts the payload by RFC 8291); a new difference goes in the README's integrations entries with the test that pins it.
- **Rich text (AngleSharp, since Phase 5; `plans/design-richtext.md` is the design).** `Campfire.RichText` has no parser of its own:
  `Html5.parseBody` parses a body with AngleSharp (pinned at 1.8.4: P1's frozen trees fail on any change, bump only with them green) and `Html5.parseIn` an
  element-context fragment. The limits Gumbo had are enforced in the parser's callbacks (400 deep, 400 attributes on an element, plus the caps: 10,000
  elements, 40,000 tokens, 400 attributes over the `html` and `body` tags), as a `ParseError` that a caller maps to what Rails' exception did; any exception
  AngleSharp itself throws (1.8.4 has a `NullReferenceException` in its select mode) is `ParseError.ParserFailed`, so parse only through `Html5`'s
  entry points. After a change here or an AngleSharp bump, re-run the security fuzz (`reference-tools/richtext/review`, `dotnet run -c Release -- N SEED`;
  `run.sh` compares with Rails in the reference image) and expect 0 violations and 0 exceptions. `Html5.innerHtml`
  is Nokogiri's serializer (`<` and `>` stay raw in attribute values, so nothing may regex-scan serialized HTML). The sanitizer is one bottom-up walk
  (`Sanitizer.scrub`) over the tree with Loofah's rules from `Loofah.fs`; autolink scans each text node's escaped form with the matchers and builds text and
  `<a target=_blank>` nodes, so no string is spliced into markup. AngleSharp makes some DOM calls quadratic: never walk siblings with
  `NextSibling`/`PreviousSibling`, never `InsertBefore` per child, never remove children from the back and never call `parser.ParseFragment`; use
  `Html5.childrenOf`, `detachChildren`, `insertAllBefore` and `parseIn` (`ContentTests` has the linear-time bound, 400 ms CPU on bodies under the caps).
  Rails is the oracle: `tests/Campfire.RichText.Tests/corpus/expected.json` (made by `reference-tools/richtext/run.sh` in the reference image) holds the
  outputs for 658 bodies, and `CorpusTests` compares plain text, editor values, mentions, presentations and `web_url` with them. Every difference lives in
  `corpus/known-differences.json`, by kind and case with a reason, and the comparison fails both ways (an unlisted difference, or a listed one that no
  longer differs). `corpus/trees.jsonl` and `context-trees.jsonl` are the trees the old Gumbo port built, frozen when it was deleted; `Html5Tests` P1 and P4
  compare the new parser with them. The known differences that are not corpus cases (end-tag lowercasing in raw text, raw-text elements in svg/math and
  table parts, limits counted on the body parse, `isindex`) are in the README's "Rich text" entry. Run `bin/verify RichText` after any change here.
- **Assets (ASP.NET Core `MapStaticAssets`, since Phase 6; `plans/design-assets.md` is the design).** There is no assets project: the App's
  `CampfireStageWebRoot` target (`Campfire.App.fsproj`, before `ResolveProjectStaticWebAssets`) stages `src/Campfire.App/Assets/vendor` (its `LOAD_PATH`

  fingerprints them. Add or change an asset by editing those directories (`bin/check-assets-incremental` proves an added or deleted override is staged or
  gone; `revendor` refreshes the vendored copy), never the staged copy under `obj/`. `Web/StaticAssets.fs` holds the table, `path` (logical path to
  fingerprinted URL), `webRootFile`, the stylesheet tags and `Link` header, and `map`; `Web/Importmap.fs` reads the import map's `pin`/`pin_all_from`.
  The table is validated at startup and a host without the web root fails at boot; `configureHost` must run on every host (tests included), and nothing may
  render a page, a broadcast or a job before `StaticAssets.map` (it fails with "static assets are not mapped"). The parity harness masks Propshaft digests
  and SDK fingerprints alike (`parity/capture/normalize.ts`, `network.ts`, `overrides.ts`, `tests/Shared/LooseDom.fs`; a plain `/assets/` URL is still a
  difference in the DOM layer). `bin/asset-check` (colima) runs the network checks N1-N4 and the probe list (encoded dots, backslashes, dotfiles,
  `/campfire.dll`, the endpoint manifest, `/wwwroot/...`) against the image; the golden fixtures are in `tests/Campfire.App.Tests/Assets/reference/`.
- **Views (Falco.Markup, since Phase 4).** Every template is an F# module at the same relative path as its ERB under
  `src/Campfire.Views/Templates/` whose `render` returns an `XmlNode` (or `XmlNode list`); a page module has `rendered ctx model :
  Layouts.ViewPage` (its `Regions` and the fragments it places), which `Pages.page` sends through `Layouts.page` (the application layout in
  `Templates/Layouts/Application.fs`, doctype included, or, for a Turbo-Frame request, turbo-rails' frame layout in `TurboRails/Frame.fs`: only
  the head and the content). A module and a namespace of one name can't both be in an assembly, so `rooms/show.html` is `Templates/Rooms/Show.fs`
  as module `ShowPage`, beside the `rooms/show/` partials' namespace. Rails' markup helpers are plain functions in `Markup/` (`Assets`,
  `Links`, `Forms`, `Turbo`, `Application`, `Users`, `Rooms`, `Messages`, `Translations`); `Helpers/` keeps only what is not markup
  (`Url`, the Unicode tables, `Application`'s text functions, the involvement words, the avatar colours, `Turbo.domId`).
  - **Encoding is `Core/Html.fs`.** Falco.Markup 1.4.0 writes attribute values and `Text.raw` unescaped, so every non-literal goes through
    `Html.attr`, `Html.text` or a `Html.Trusted` value; `bin/lint-markup` (run by `bin/verify`, with `--self-test` over
    `tests/lint-markup/planted/`) refuses anything else anywhere under `src`. An attribute's name is always a literal (`Html.attr "data-x"
    v`; pass built `XmlAttribute`s, never names, to a helper). HTML never comes from a string: no `HtmlOutput.text`/`ofBytes` or
    `CachedFragment` from a string outside `Core/`, and no `Pages.html`/`renderText`/`renderAs` body served as HTML, a Turbo Stream or SVG
    (render with Falco, `Pages.renderOutput`). `Core/Html.fs` is exempt, so its definitions are pinned in the lint (`EXEMPT_SURFACE`). Keep
    Falco's modules qualified (`Attr.x`, `Text.x`, `Elem.x`; no `open Falco.Markup.Attr`, no `module T = Text`) and never use Falco's
    auto-opened `_a [ _href_ v ]` spelling; the lint refuses both. A URL attribute from data (`href`, `src`, `poster`, `data-*-url-value`) comes from a route or an asset path; mark any
    user-supplied URL for the gate's XSS review. `Html.Trusted` values come from a few makers only: `ofSanitized` (rich text, which rewrites
    `<` in attribute values to U+E000, so the serializer that replaces the sanitizer must keep escaping `<` in attribute values or keep that
    rewrite), `ofAssetTags` (the stylesheet and import map tags, `ViewContextBuilder`) and `ofAccountStyles` (the account's CSS; it writes a
    `</style` as `<\/style`).
  - **Pages and fragments.** `HtmlOutput` (`Core/HtmlOutput.fs`) is a rendered page in parts: UTF-8 text parts with a `CachedFragment`
    between each two (`Html.fragment` is the slot a template places one with). `Pages.send` writes it and keeps its compressed form in
    HybridCache by the SHA-256 of its parts. Fragments (`Core/Fragments.fs`, the only file that calls HybridCache; the lint enforces it) are
    fetched up front and awaited by the presenters, controllers and broadcasts (`MessagesCached`, `BoostsCached`, `UsersCached`), never by a
    template, which takes `CachedFragment`s as arguments. A miss builds the view inside the factory (the context is used one step at a time:
    fetch in order, never `WhenAll`).
  - **Whitespace.** Where the ERB has whitespace between inline siblings write `Html.sp`; inside a custom element whose script inserts siblings
    (`lexxy-editor`) keep the space the ERB leaves before its child. The loose DOM drops a space at an element's edge with no sibling before it
    (the `.message__room` arrow of a search result, the lexxy prompt's space): only `bin/pixel-parity` sees those, so run each slice on every
    seed after touching a template, and expect a partial to show up in a slice you did not touch. `Html.unclosed "form" node` is the block-less
    `form_with` (`sessions/transfers/show`).
  - **Odds and ends the oracle taught.** `Markup.Forms` takes an empty object name for a model-less form; write `readonly` and `checked` bare
    (`Attr.readonly`, `Attr.checked'`) where the ERB does; a textarea goes through `Forms.textArea` (its leading newline); the macOS steps'
    `em` holds U+F8FF as the ERB does (the loose DOM sees an empty text node without it). `pwa/manifest.json` is `Manifest.render ... :
    byte[]` on `Utf8JsonWriter` (the oracle compares it as JSON, `Facts.jsonEqual`); the service worker stays text. A custom element's flex
    children still get `Html.sp` between two inline siblings.
  - **The oracles** (`tests/Campfire.Views.Tests`): `tests/Shared/LooseDom.fs` is the harness's loose DOM in F# (AngleSharp), pinned to

    `Cases/` (`Operations.fs`, `Pages.fs`, `Rest.fs`: what each case calls, the case runners). Markup answers must be equal as the loose DOM; text
    answers (URLs, JSON, numbers) equal as text; fragment offsets, not lengths, are compared. The file is frozen: it was written once by a

- TLS end to end (Phase 7 unit 7.5, plans/design-front.md F16). **The gate's TLS states**: `bin/pixel-parity --candidate-tls` (or `PARITY_CANDIDATE_TLS=1` with
  `parity/bin/candidate`) starts the candidate with `TLS_DOMAIN=campfire.localhost`, `HTTPS_PORT` = its port, `HTTP_PORT=80` (published on port + 100) and a
  self-signed P-256 certificate (valid from 2020, because the clock is frozen at the seed's instant) written into its `storage/thruster` as a `DirCache`
  file before boot, so no order is made; the browser sees it at `https://campfire.localhost:<port>` (`--actual-origin`; the normalized layers read that origin
  as the shared `http://localhost:3999`, and the harness's seeded `Math.random` ignores the origin). The reference stays on HTTP. Use it for
  `--only 'auth/sign_in,rooms/show/designers'`. **The image against Pebble**: `reference-tools/front/pebble-image.sh [IMAGE]` (colima; the image needs a
  `parity/bin/candidate build`) runs Pebble and the image on host networking (`TLS_DOMAIN=campfire.test`, `HTTP_PORT=5002`, `ACME_DIRECTORY`, `SSL_CERT_FILE`
  = Pebble's root), and checks the order at boot, the cache files and their modes, the 2-certificate chain and that a restart loads the cache without a
  second order.
  **Operator step, Let's Encrypt staging (human-gated; not run by any agent)**: before a release that touches `Web/Acme.fs` or `Web/Host.fs`, on a host whose
  DNS name points at it with ports 80 and 443 reachable, run the image with `TLS_DOMAIN=<name>`, `ACME_DIRECTORY=https://acme-staging-v02.api.letsencrypt.org/directory`,
  a persistent `/rails/storage`, and `SSL_CERT_FILE` unset (the app trusts the system roots). Expect `Loaded` or `ordered` in the log within about a minute,
  `storage/thruster/<name>` and `acme_account+key` at 0600, `curl -vI https://<name>/up` to say HTTP/2 and a "(STAGING)" issuer (the staging root is not
  trusted, so `-k` or the staging root with `--cacert`), `curl -I http://<name>/` a 301 to `https://<name>/`, then a restart that logs the cached load and makes no
  new order (Let's Encrypt staging limits are generous but not infinite: one order per name per run). Then remove the staging certificate from the cache
  (delete `storage/thruster/<name>`) and start again with the production directory, which is the default. Failures to report: a 421 on the HTTP port for the
  right name (check `TLS_DOMAIN` spelling and the Host the client sends), or an order that logs a CA error (the log names the problem; the app retries in
  30-60 minutes).
